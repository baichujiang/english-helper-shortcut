## 已完成的静态检查

- 动作输出引用均能找到对应 UUID。
- 正式流程只包含一个写入剪贴板动作，紧跟可取消的确认框。
- 没有打开其他 App、打开 URL、下载 URL 或运行脚本的动作。
- 模型固定为 `Apple Intelligence on Device`。
- 最终47步版本的控制流分组完整，文本匹配使用正确的变量格式，源文件可通过Python编译检查。
- 四个分发文件通过Apple Archive签名校验，内含动作和设置与XML源码一致。签名工具移除文件名派生的名称并更新客户端版本，这两个元数据字段不参与逐值比较；源码与文件SHA-256写入manifest。

- 镜像不显示辅助触控浮层。最终“在原输入框复制 → 小白点 → 检查 → 确认 → 原框粘贴”的手机实操需单独记录，不能仅凭设置绑定或快捷指令资料库运行推断通过。
- 用户进行正式版小白点实测时反馈：有错误的测试句显示没有错误。此项尚未通过，正在核对实际剪贴板输入、绑定版本和模型结果；前述资料库内的单项通过不能覆盖这一问题。

## 实测发现并修正

1. 文本匹配参数 `text` 需要 `WFTextTokenString`。最初使用附件格式导致默认输入提示，已修正；Mac 运行已直接进入模式菜单。
2. 单次 Dictionary 输出的中文解释出现与实际修改不符的内容；独立生成理由又发生系统模型拒答。第一版因此只提供原文与实际修改版对照，避免展示不准确的理由。
3. 成功末尾清空返回值，避免从另一个快捷指令调用或 CLI 验收时额外要求输出文本授权；不影响已确认的复制。
4. 手机快捷指令资料库曾只显示14项，而 Spotlight 可见新导入的项目；新版本同步状态必须以手机实际运行确认。
5. 中英混合输入曾被模型翻译。已加强保持英文的提示，并在预览前比较两份文本中的Han字符序列；中文被增删或改变时停止，不执行复制。实际复测保留了中文与英文，但仍可能合并换行。
6. 手机 iCloud 云盘未开启，资料库初始显示旧内容。通过本机临时 HTTP 页面在手机 Chrome 下载签名文件，并使用“打开方式 → 快捷指令”实际完成正式版导入；随后资料库刷新出现此前的测试工具。隔空投送显示已发送，但未观察到导入页面，不能以发送成功作为安装证据。
7. 旧验收工具仅按名称调用正式版，在 iPhone 出现“未找到快捷指令”；合成测试句已成功写入，手动运行正式版可继续。验收脚本改为准备测试剪贴板后提示手动运行，避免依赖跨设备的指令引用。正式产品没有调用其他快捷指令的动作，不受此问题影响。
